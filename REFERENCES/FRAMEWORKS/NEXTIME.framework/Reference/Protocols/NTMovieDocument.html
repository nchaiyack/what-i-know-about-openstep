NTMovieDocument


Adopted By: NTMovieDocument


Incorporates: NSObject


Declared In: NEXTIME/NTMovieDocument.h  



Protocol Description


This protocol specifies basic behavior for an object that plays a movie.  (A movie consists of any time-based multimedia data, such as video, audio, or both.)  The protocol's methods fall into two groups: those concerned with playing or stopping the movie, and those concerned with setting or retrieving the movie's position in time.  No methods are included for recording or editing a movie.


The NTMovieDocument class adopts this like-named protocol by adopting the NTExtendedMovieDocument protocol, which incorporates the NTMovieDocument protocol.


A class conforming to the NTMovieDocument protocol might manage either a software playback system (such as the NEXTIME server, which can read movie data from files) or a hardware playback system (such as an external videocassette deck, whose video and audio data may be inaccessible to the computer).  The NTMovieDocument class is an example of the former type—it communicates with the NEXTIME server to open a movie file, control the movie's playback, receive updates on the movie's status, and edit the movie using the pasteboard.  By contrast, a typical hardware system such as a videocassette player wouldn't ever manipulate files or the pasteboard, so such methods aren't part of this protocol.  Similarly, this protocol includes no methods for drawing the video image in a window, because some playback systems display their video on an external device.  (Drawing methods are included in  the NTMovieDrawing protocol.)



Interacting with an NTMovieControlView



Usually, an application that plays movies lets the user control the playback.  To control an object that conforms to the NTMovieDocument protocol (hereafter simply called a “movie document object”), it's convenient to use an NTMovieControlView.  First, send the NTMovieControlView a setMovieDocument: message with your movie document object as the argument.  The buttons and slider in the NTMovieControlView will then be able to send four control messages to your movie document object: play:, pause:, reset:, and setCurrentPosition:.  Each of these methods should return a boolean value indicating whether the operation was successful; if it wasn't successful, the NTMovieControlView can then prevent the button or slider from changing to the new state.   (The NTMovieDocument class returns YES in all cases, because the NEXTIME server can change a movie from any state to any other state, by virtue of being a software playback system.  By contrast, some hardware devices can't handle certain state transitions.  For example, some laserdisc players can't go directly from a stopped state to fast forward, without first being put in a playback state. In such cases, the corresponding method of the movie document object should either put the hardware device into the intermediary state before moving it to the requested state, or else return NO to indicate the transition is impossible.)


A movie document object can also intervene to modify the NTMovieControlView's state.  For example, on receiving a setCurrentPosition: message, the movie document object can query the NTMovieControlView for its current position, and adjust that position slightly to reflect the precise starting point of the corresponding video frame.


A number of the NTMovieDocument protocol's methods post notifications to inform observers of changes in the movie's current position in time or its playback state—paused, playing normally, and so forth.  When you send the NTMovieControlView a setMovieDocument: message, it registers as an observer to receive your movie document object's notifications, so it can update its buttons and slider accordingly.  See the NTMovieDocument class specification for details on these notifications.


For related information, see “NTMovieControlView's Movie Document Object” in the NTMovieControlView class specification.



Specifying Positions in Time



The NTMovieDocument protocol expresses a movie's position in terms of seconds from the start of the movie.  The position, represented by a double-precision floating-point number, changes continually during playback to reflect the time elapsed since the beginning of the movie.  You can jump to a different point in the movie by invoking setCurrentPosition:.


Normally, a movie starts its playback at time zero, corresponding to the first frame, and continues until the final frame in the movie (assuming the user doesn't interrupt the playback).  However, a movie file can contain information limiting playback to a certain range within the movie.  The minPosition and maxPosition methods retrieve this range.  Playback starts at the minimum position (which is usually, but not necessarily, zero seconds) and continues until the maximum position (which usually, but not necessarily, corresponds to the movie's final frame).  The NTMovieDocument protocol's methods should never position the movie before minPosition or after maxPosition.  The designer of a movie file might have special uses in mind for the portions of the file before minPosition and after maxPosition.  For example, these portions might contain a preview of the movie.


Positions measure the point in time at which a frame starts to be displayed.  Each frame is typically displayed for a small fraction of a second, determined by the movie's frame rate.  Thus, maxPosition returns the time at which the last playable frame starts to be displayed, not the time at which it ends.  Similarly, if you invoke setCurrentPosition: with a time that's part of the way through a frame's duration, the system might adjust this value to the time at which the frame starts.   (This is true of the NEXTIME server and thus of the NTMovieDocument class's implementation of setCurrentPosition:.  Many hardware devices similarly adjust the requested position.)


NEXTIME doesn't assume a constant frame rate over time, nor does it even assume that the frames in a movie are ordered in a linear fashion.  (Each frame of a NEXTIME movie file is time-stamped, so they can be stored in any order.  This feature simplifies editing.)  Specifying a position by the frame number could have unexpected results, so this high-level programming interface allows positions to be expressed only in seconds.

currentPosition


- (double)currentPosition 


Returns the document's current position within the movie, in units of seconds.


See also:  - setCurrentPosition:, - frameForPosition: (NTMovieDocument class)



maxPosition


- (double)maxPosition 


Returns the document's maximum possible position within the movie, in units of seconds.  This is the time at which the last playable frame begins to be displayed.


See also:  - minPosition



minPosition


- (double)minPosition 


Returns the document's minimum possible position within the movie, in units of seconds.


See also:  - maxPosition



pause:


- (BOOL)pause:(id)sender 


Stops playback without resetting the current position.  If the movie is playing when the method is invoked, playback is stopped, and the notification NTMovieDocumentDidStopPlaybackNotification is posted.


Software playback systems don't usually discriminate between a stopped and a paused state.  Hardware systems, on the other hand, treat these very differently.  For example, with many hardware devices, playback can resume immediately if the hardware is in a paused state, but only after a delay if it's in a stopped state.  Also, some hardware devices automatically move from a paused to a stopped state after a few minutes of inactivity.  Software control systems should take this behavior into account if they intend to control hardware players.  A hardware movie document should post the notification NTMovieDocumentDidPausePlaybackNotification when pausing the movie, and NTMovieDocumentDidStopPlaybackNotification only when the hardware has actually moved to a stopped state.


This method is typically invoked by an NTMovieControlView object when the user presses that object's Pause button.  Returns YES if the request to pause is acceptable, or NO to indicate that the request should be disregarded.



play:


- (BOOL)play:(id)sender


Starts playback from the current position.  If the movie is playing in fast forward or reverse, playback is stopped, and the notification NTMovieDocumentDidStopPlaybackNotification is posted.  Before beginning playback, the receiver posts the notification NTMovieDocumentWillStartPlaybackNotification.  While playing, it periodically posts the notification NTMovieDocumentDidSetPositionNotification to indicate the current position in the movie.  Observers can use this information to update their state and position displays.  If the end of the movie is reached, playback is automatically stopped, and the notification NTMovieDocumentDidStopPlaybackNotification is posted; observers should update their user interface accordingly.  


This method is typically invoked by an NTMovieControlView object when the user presses that object's Play button.  Returns YES if the request to play is acceptable, or NO to indicate that the request should be disregarded.



playLooped:


- (BOOL)playLooped:(id)sender


Starts “looped” playback, meaning that as soon as the movie reaches the end, it will immediately start playing again at the beginning, and this process will repeat continuously until playback is stopped or otherwise interrupted.


This convenience method works by alternately invoking the play: and setCurrentPosition: methods.  First play: is invoked, initiating a single playback of the movie (starting from the current position).  When the end of the movie is reached,  the setCurrentPosition: method is invoked to return the document to its minimum position, after which the play: method is invoked again, and so on. Each time the end of the movie is reached, the notification NTMovieDocumentDidStopPlaybackNotification is posted.


Returns YES if  the request for looped playback is acceptable, or NO to indicate that the request should be disregarded.



reset:


- (BOOL)reset:(id)sender 


Stops any current playback and resets the receiver's position to the beginning of the movie.  If the movie is playing when the method is invoked, playback is stopped and the notification NTMovieDocumentDidStopPlaybackNotification is posted.  The movie position is reset to the start of the movie, and the notification NTMovieDocumentDidSetPositionNotification is posted.  Finally, the movie's poster frame is displayed, and the notification NTMovieDocumentDidShowPosterFrameNotification is posted.  (The poster frame is a video frame that someone has chosen as the best still image for representing the movie; it defaults to the movie's first frame, but could be any frame in the movie.)


This method is typically invoked by an NTMovieControlView object when the user presses that object's Reset button.  Returns YES if  the request for to reset the movie is acceptable, or NO to indicate that the request should be disregarded.



setCurrentPosition:


- (void)setCurrentPosition:(double)position 


Sets the document's current position to position, expressed in seconds from the beginning of the movie.   If the document is playing when the method is invoked, playback is stopped, and the notification NTMovieDocumentDidStopPlaybackNotification is posted.   After the receiver has updated its position, the notification NTMovieDocumentDidSetPositionNotification is posted to inform observers of the current position.


This method is typically invoked by an NTMovieControlView object when the user adjusts that object's position slider. 


See also:  - currentPosition
