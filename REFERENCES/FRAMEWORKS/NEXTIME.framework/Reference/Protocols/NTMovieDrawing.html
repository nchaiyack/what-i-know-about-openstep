NTMovieDrawing


Adopted By: NTMovieDocument


Declared In: NEXTIME/NTMovieDocument.h  



Protocol Description


The NTMovieDrawing protocol controls the drawing of a movie's video data in an NTMovieScreenCell.  Methods are provided to identify the NTMovieScreenCell to the video server, to display the current video frame, and to suspend the drawing of the movie while other systems (such as the Application Kit) are drawing into the same region of the screen.


The NTMovieDocument class implements this protocol to communicate drawing requests to the NEXTIME server.  (You can create other classes that do likewise.  However, such classes should inherit from NTMovieDocument, to avoid having to re-implement its mechanism for establishing a connection and a drawing context.)  Another sort of class might manage a video display system other than the NEXTIME serve but still use the NTMovieDrawing protocol to display the video in an on-screen window.  Classes that cause video to be displayed elsewhere—such as on a separate monitor attached to a laserdisc player—can implement the NTMovieDocument protocol, but wouldn't use the NTMovieDrawing protocol.


By default, the NTMovieScreenCell class invokes NTMovieDocument's implementation of this protocol's methods.  However, you can have the NTMovieScreenCell use another kind of object, by specifying that object as the argument to NTMovieScreenCell's setRepresentedObject: method.  The object (hereafter called the “movie document object”) must conform to the NTMovieDocument and NTMovieDrawing protocols.  You can also subclass NTMovieScreenCell.

Instance Methods 


display


- (void)display 


Displays or redraws the current video frame.  The NTMovieScreenCell associated with the current  display context must already be configured—that is, its frame rectangle and the rectangle containing the video image should have been determined and communicated to the video server.  This message is typically sent by NTMovieScreenCell's drawInteriorWithFrame:inView: method, in which case the NTMovieScreenCell will already be configured.


See also:   - setViewID:, updateFrame: (NTMovieScreenCell)



isDrawingSuspended


- (BOOL)isDrawingSuspended 


Returns YES if drawing is currently suspended; NO otherwise.


See also:  - suspendDrawing



resumeDrawing


- (void)resumeDrawing


Resumes video output.  If the movie isn't currently playing, only the current frame is redrawn.  This method is usually invoked when the NTMovieScreenCell finishes resizing or scrolling.


See also:  - suspendDrawing



setViewID:


- (void)setViewID:(int)viewID 


Sets the view ID used to register the NTMovieScreenCell with the NEXTIME server (or with another software system for video playback, if the class implementing this protocol doesn't use the NEXTIME server).  This token is used to indicate which NTMovieScreenCell the movie will be displayed in.


The NTMovieScreenCell should send this message to the movie document object after connecting to the server's display context, and before sending the movie document object a display message.  The viewID argument must be non-zero, and it must be unique for each NTMovieScreenCell within the application.  Typically, viewID is the id, cast as an integer, of the NTMovieScreenCell invoking this method, as follows:


[[self representedObject] setViewID:(int)self];


See also:  - viewID (NTMovieDocument class)



suspendDrawing


- (void)suspendDrawing 


Temporarily suspends video output, until a resumeDrawing message is received.  This method is usually invoked when the NTMovieScreenCell is about to be resized or scrolled.


See also:   - isDrawingSuspended
