NTMovieControlView 


Inherits From: NSView : NSResponder : NSObject  


Conforms To: NSCoding

NSObject (NSObject)


Declared In: NEXTIME/NTMovieControlView.h  





Purpose


An NTMovieControlView lets the user control a movie's playback.  It  includes a play button, a position scroller, and a volume control.



Principal Attributes

• Lets the user play and pause a movie, or skip to any point in the movie

• Scroller knob reflects the movie's current position in time

• Communicates with an NTMovieDocument, or a similar object

• Often used along with an NTMovieScreen


Creation

initWithFrame: Creates an NTMovieControlView of the specified width.


Commonly Used Methods

setMovieDocument: Sets the movie that will be controlled.





Class Description 


NTMovieControlView provides a basic user interface—a play button, a position scroller, and a volume control—for controlling the playback of a movie.  The nature of the movie—whether it contains video, audio, or some other data type, whether it's stored in a file or on external media, and even whether it's digital or analog—is immaterial to the NTMovieControlView.  Such details are known only to an intermediary object to which the NTMovieControlView sends its control messages.  This intermediary object, which must conform to the NTMovieDocument protocol, translates the control messages into whatever actions are appropriate for the particular type of movie it manages.  Most commonly, this “movie document object” will be an instance of the NTMovieDocument class, which communicates with the NEXTIME server to play a movie file.



User Interface Controls



The NTMovieControlView's play button is a toggle control that becomes a pause button while the movie is playing.  Pausing the movie stops playback while maintaining the current position.


By default, the position scroller consists only of a knob in a horizontal bar.  During playback, the knob automatically moves to the right along the bar, reflecting the current point in time.  The user can drag the knob to skip to any point in the movie.  If the NTMovieControlView's movie document object conforms to the NTExtendedMovieDocument protocol, the scroller will also include scroll buttons for single-stepping through the movie's frames, forward or backward.


The volume control is a button that user presses to pop up a vertical slider for setting the audio's volume.



NTMovieControlView's Movie Document Object



An NTMovieControlView is ineffectual until you assign it a movie document object by invoking setMovieDocument:.  Thereafter, the user's actions with the NTMovieControlView will be translated into play:, pause:, setCurrentPosition:, stepForward:, and stepReverse: messages sent to the movie document object.


The communication isn't one-way.  The movie document object also provides feedback to the NTMovieControlView, by way of notifications that the NTMovieControlView has registered to receive.  For example, the movie document object periodically posts the notification NTMovieDocumentDidSetPositionNotification as the movie is playing.  When it receives this notification, the NTMovieControlView sends the movie document object a currentPosition message to get the new position.  In this way, the NTMovieControlView continually updates the position of its scroller's knob during playback.


Furthermore, multiple objects can control a single movie document object.  In the most common case, both an NTMovieControlView and an NTMovieScreenCell send play: and pause: messages to an NTMovieDocument.  If the user clicks the mouse in the NTMovieScreenCell, the NTMovieDocument is sent a play: or pause: message.  The NTMovieDocument then posts the corresponding notification (NTMovieDocumentWillStartPlaybackNotification or NTMovieDocumentDidPausePlaybackNotification).  When the NTMovieControlView receives this notification, it toggles its play button accordingly.


Here's the complete list of notifications that the NTMovieControlView registers to receive from its movie document object:


NTMovieDocumentWillStartPlaybackNotification

NTMovieDocumentWillStartFastForwardNotification

NTMovieDocumentWillStartFastReverseNotification

NTMovieDocumentDidStopPlaybackNotification

NTMovieDocumentDidPausePlaybackNotification

NTMovieDocumentDidSetPositionNotification

NTMovieDocumentDidEditMovieNotification


The NTMovieControlView's response to some of these has already been mentioned.  Notifications of fast forward and fast reverse playback are handled in exactly the same way as normal playback.  Similarly, notification of stopped playback is handled in the same way as paused playback.  The notification NTMovieDocumentDidEditMovieNotification is different.  Upon receipt of this notification, the NTMovieControlView queries the movie document object for its minimum, maximum, and current positions, and then updates the position scroller accordingly.


For more information on the communication between an NTMovieControlView and its movie document object, see “Interacting with an NTMovieControlView” in the NTMovieDocument protocol specification.



Replacing NTMovieControlView with Another Class



NTMovieControlView is a convenience class that helps NEXTIME applications present a consistent user interface.  It's not designed to be subclassed.  Nonetheless, if NTMovieControlView doesn't suit your application's needs, you can instead use any group of NSControls whose target is an NTMovieDocument (or some other object that conforms to the NTMovieDocument protocol).  In this case, some object in your application should register to receive notifications from the NTMovieDocument, updating the status of the NSControls as appropriate when notifications are received.

Instance Methods 



currentPosition


- (double)currentPosition 


Returns the current position in time, as shown by the scroller's knob.  The return value is expressed in seconds from the movie's beginning.


See also:  - setCurrentPosition:



initWithFrame:


- (id)initWithFrame:(NSRect)frameRect 


Initializes an NTMovieControlView object based on the frame rectangle frameRect.  Only the width and origin of frameRect are used; the receiver's height is set to that of a horizontal NSScroller.  This method creates the play button, the volume button, and the position scroller, but no scroll buttons are created yet.  Returns self. 


See also:  - setMovieDocument:



maxPosition


- (double)maxPosition 


Returns the position in time of the movie's last playable frame.


See also:  - maxPosition (NTMovieDocument protocol), - minPosition



minPosition


- (double)minPosition 


Returns the position in time of the movie's first playable frame.


See also:  - minPosition (NTMovieDocument protocol), - maxPosition



movieDocument


- (id <NTMovieDocument>)movieDocument 


 Returns the movie document object that the receiver is currently controlling.


See also:  - setMovieDocument:



setMovieDocument:


- (void)setMovieDocument:(id <NTMovieDocument>)anObject 


Sets the receiver's movie document object to anObject.  anObject must conform to the NTMovieDocument protocol, or the exception NTMovieControlViewIllegalMovieDocumentException is raised. 


The receiver updates its user interface to reflect the new movie document object in several ways.  The scroller's knob shifts to show the movie's current position.  If anObject conforms to the NTExtendedMovieDocument protocol, scroll buttons are added to let the user step forward or backward one frame at a time.  If anObject responds to a documentState message, the play button is updated to reflect whether the movie is playing or stopped; otherwise the button stays in its current state.


During archiving, the receiver will conditionally archive anObject.


See also:  - movieDocument



setCurrentPosition:


- (void)setCurrentPosition:(double)position 


Skips to a new position in the movie, shifting the scroller's knob to reflect the change.  position expresses the desired number of seconds from the beginning of the movie.  The receiver clips position to the range bounded by its minimum and maximum positions, and then sends the clipped position in a setCurrentPosition: message to the movie document object.  This method does nothing if no movie document object is associated with the NTMovieControlView.


See also:  - maxPosition, - setMovieDocument:, - currentPosition



setState:


- (void)setState:(NTMovieState)state 


Sets the receiver's playback state to state.  The NTMovieState enumeration consists of the following values:


NTMovieStateStopped

NTMovieStatePaused

NTMovieStatePlaying

NTMovieStateFastForward

NTMovieStateFastReverse


However, the NTMovieControlView class provides no controls for fast-forward or fast-reverse playback, so if state is NTMovieStateFastForward or NTMovieStateFastReverse, the message is interpreted as though state were NTMovieStatePlaying.  


The receiver sends its movie document object a play:, pause:, or reset: message, depending on state.  If the message returns NO, the NTMovieControlView keeps its old state.  Otherwise, it toggles the play button, if needed, and switches to state.


See also:  - state



state


- (NTMovieState)state 


Returns the receiver's current playback state.  If the receiver has just been initialized, its state is NTMovieStateStopped.


See also:  - setState:
