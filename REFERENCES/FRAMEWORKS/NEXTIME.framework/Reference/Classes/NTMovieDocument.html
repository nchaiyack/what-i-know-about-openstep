Purpose

An NTMovieDocument manages a single NEXTIME movie, usually by displaying it in an NTMovieScreen and receiving control messages from an NTMovieControlView.


Principal Attributes

• Operations include play, pause, reset, fast forward or reverse, and step forward or backward.

• Notifications report changes in the movie's playback status and its position in time.

• Movies can be edited using the pasteboard.


Creation

initByReferencingFile: Creates an NTMovieDocument from the specified movie file.

initWithPasteboard: Creates an NTMovieDocument from the movie data in the pasteboard.


Commonly Used Methods

play: Starts playback from the current position in time.

pause: Stops playback, maintaining the current position.

setCurrentPosition: Sets the position within the movie, measured in seconds. 





Class Description 


An NTMovieDocument represents a single NEXTIME movie.  This class lets you open a movie file, play back the movie, and edit the movie data.  An NTMovieDocument isn't itself a graphical object.  Instead, it functions as an easy-to-use representative of the NEXTIME server, handling the communication between the server and graphical user interface classes such as NTMovieScreen, NTMovieScreenCell, and NTMovieControlView.


The most convenient way to create an NTMovieDocument is by invoking NTMovieScreen's setMovieFile: method, which in turn invokes NTMovieDocument's initByReferencingFile: method.  Thereafter, the movie represented by the new NTMovieDocument will be displayed in the NTMovieScreen.  To give the user buttons and a slider for controlling the movie, you can associate the NTMovieDocument with an NTMovieControlView by sending the latter object a setMovieDocument: message.  (See the NTMovieControlView class specification, as well as “Interacting with an NTMovieControlView” in the NTMovieDocument protocol specification.)


However, you can also create an NTMovieDocument directly and control it from other objects in your application.



Editing



The NTMovieDocument class adopts several protocols whose methods specify how to play back movies.  To allow more than just playback, however, NTMovieDocument declares additional methods for editing movies, such as cut:, copy:, paste:, and setSelectionStartingPosition:endingPosition:.


These editing operations don't immediately alter the movie file, but neither do they copy the actual edited movie frames into memory.  Multimedia data is often too immense for such an approach.  Instead, the NEXTIME server keeps information about the edits in an “edit decision list” in memory.  The edit decision list simply records the cumulative effect of the editing operations, maintaining a roster of which frames were ostensibly moved or deleted.  Some movie file formats, such as QuickTime¾, themselves include an edit decision list, in which case the movie's frames don't need to be rearranged even when the file is saved.  When you save such a movie using writeToFile:atomically:, you can choose either to leave the frames untouched or to “flatten” the file, removing deleted frames.

Class Methods


canInitWithPasteboard:


+ (BOOL)canInitWithPasteboard:(NSPasteboard *)pasteboard 


Returns YES if the receiver can initialize the receiver with movie data from pasteboard; otherwise, returns NO.  The pasteboard must contain a supported movie pasteboard type for this method to return YES.


See also:   + moviePasteboardTypes



readableMovieFileTypes


+ (NSArray *)readableMovieFileTypes


Returns an array of NSString objects listing all the  movie data file types that can be read.  For example, QuickTime movies are included in the list. The complete list depends on which NTFileParser objects are present in the server; new movie types can be added by installing new NTFileParser components.


See also:  + writablemovieFileTypes 



moviePasteboardTypes


+ (NSArray *)moviePasteboardTypes 


Returns an array of NSString objects listing the types of pasteboard data that can be pasted into an NTMovieDocument.  The only one is NTMoviePboardType.


See also:   + canInitWithPasteboard:



writableMovieFileTypes


+ (NSArray *)writableMovieFileTypes 


Returns an array of NSString objects listing all the movie data file types that can be written, such as the QuickTime movie type. The complete list depends on which NTFileWriter objects are present in the server; new movie types can be added by installing new NTFileWriter components.


See also:   + readableMovieFileTypes

 Deletes the selected portion of the document. This method posts the notification  NTMovieDocumentDidEditMovieNotification with the receiving object to the default notification center.

documentState


- (NTMovieState)documentState 


Returns the current playback state of the NTMovieDocument—playing, paused, stopped, playing in fast-forward mode, or playing in fast-reverse mode.

filename


- (NSString *)filename 


Returns the name of the current movie file, expressed as an absolute pathname. If the movie hasn't been explicitly stored in a file (for example, if it was initialized from the pasteboard), this method returns the name of a temporary file.


See also:  - init



frameForPosition:


- (int)frameForPosition:(double)position 


Returns the number of the video frame at position seconds from the start of the movie, or -1 if there is no valid video frame at position.  Frames are numbered starting with zero at the beginning of the file.  This is method is needed if you want to retrieve the frame shown at a particular time in the movie, because NEXTIME doesn't assume a constant frame rate over time, nor does it assume that frames are ordered by time in the movie file.  (Each frame is time-stamped, allowing arbitrary ordering.)



init


- (id)init 


Initializes the newly allocated NTMovieDocument without yet associating it with any movie data.  The movie is given a temporary, unique filename, such as “UNTITLED.mov”.  The NEXTIME server actually writes a temporary file with this name, deleting it when writeToFile:atomically: is invoked.  The temporary file is created in the current working directory (as determined by the NSFileManager object).


The only way to associate movie data with an NTMovieDocument instance that was initialized with this method is to invoke paste:.


See also:  - filename



initByReferencingFile:


- (id)initByReferencingFile:(NSString *)path 


Initializes the new NTMovieDocument from the data in the file whose absolute pathname is path. The file is assumed to persist and will be reread later during operations on the movie.  The notification NTMovieDocumentDidOpenMovieNotification is posted.  Returns nil if the file can't be opened.



initWithPasteboard:


- (id)initWithPasteboard:(NSPasteboard *)pasteboard 


Initializes the new NTMovieDocument with the data in pasteboard.  This method invokes init, then pastes the data and posts the notification NTMovieDocumentDidOpenMovieNotification.  Returns nil if the pasteboard data is corrupt or of an inappropriate type. 



movieParameters


- (NSDictionary *)movieParameters 


Returns the receiver's userinfo dictionary, which contains descriptive information about the current movie.  The contents of this dictionary are determined by whichever NEXTIME components are installed in the server.  Typical contents are described under “Items Common to Most NTMovieDocument Notifications” in the Notifications section of this class specification.


See also:  - movieProxy



movieProxy


- (id)movieProxy 


Returns the proxy to an object in the NEXTIME server that conforms to the NTMovie protocol.  This object represents the current movie.  You can use the proxy to obtain more information about the movie than the movieParameters method provides.


See also:  - controllerProxy



paste:


- (void)paste:(id)sender 


Replaces the selected portion of the document with the contents of the pasteboard.  This method posts the notification NTMovieDocumentDidEditMovieNotification with the receiving object to the default notification center.


See also:  - copy, - cut:



selectNull


- (void)selectNull


Deselects the current selection.  This method posts the notification NTMovieDocumentDidMakeSelectionNotification with the receiving object to the default notification center.


See also:  - setSelectionStartingPosition:endingPosition:



selectionEndingPosition


- (double)selectionEndingPosition 


Returns the ending position of the current selection, expressed in seconds from the beginning of the movie. This is the time at which the final frame in the selection will start to be displayed, not the time (a fraction of a second later) at which it stops being displayed.


See also:  - setSelectionStartingPosition:endingPosition:



selectionStartingPosition


- (double)selectionStartingPosition 


Returns the starting position of the current selection, expressed in seconds from the beginning of the movie.


See also:  - setSelectionStartingPosition:endingPosition:



setSelectionStartingPosition:endingPosition:


- (void)setSelectionStartingPosition:(double)start endingPosition:(double)end 


Selects the portion of the movie from the position start through the position end.  These two positions  specify starting and ending times, expressed in seconds from the beginning of the movie.  (end specifies the last frame's starting time, not the time when it stops being displayed.)  If there isn't a key frame located precisely at start, the selection will be adjusted so that it actually starts with the last key frame prior to start.  Similarly, if no key frame coincides exactly with end, the selection is adjusted so that its final frame is the last key frame before end.  After any necessary adjustments have been made, the notification NTMovieDocumentDidMakeSelectionNotification is posted.


See also:  - selectionStartingPosition, - selectionEndingPosition, - frameForPosition:



viewID


- (int)viewID


Returns the identification number used to register the NTMovieScreenCell with the NEXTIME server.


See also:  - setViewID: (NTMovieDrawing protocol)



writeToFile:atomically:


- (BOOL)writeToFile:(NSString *)path atomically:(BOOL)useAuxiliaryFile 


Writes the movie contents of the receiver to path, which should be an absolute pathname. The suffix of path is used to determine the proper file format, and should be a suffix found in the NSArray returned by the writableMovieFileTypes class method.


If path matches the current filename and useAuxiliaryFile is NO, the movie data is written directly to path.  (This operation can be very fast if the file format includes an edit decision list—as does the QuickTime format—instead of requiring any edited samples to be rewritten.)


On the other hand, if useAuxiliaryFile is YES or the file is being saved to a new pathname, the data is written to an auxiliary file named path~, which is then “flattened” by resolving external data references and removing unused samples and tracks.  Finally, the auxiliary file gets renamed to path, replacing the original file with the new, flattened movie data.  In the case where path matches the current filename, the YES option guarantees that the original file won't be corrupted even if the system should crash during writing.  However, it's a much more time-consuming option, and if there isn't enough disk space for two copies of the movie file, the attempt to write the file will fail and this method will return NO.


Once the file is successfully written, the name of the movie (as returned by the filename method) is updated to path, and the notification NTMovieDocumentDidRenameMovieNotification is posted. Returns YES if the file is written successfully, and NO if path has an invalid suffix or the file can't be saved.


See also:  - init



Notifications 


NTMovieDocument uses two types of notifications: those posted synchronously to the default notification center, and those enqueued asynchronously for posting to the default notification center.  All of NTMovieDocument's asynchronous notifications are enqueued with the default NSNotificationQueue, and they all use the posting style NSPostASAP.  The descriptions below specify whether each notification is typically posted synchronously or asynchronously.



Items Common to Most NTMovieDocument Notifications



Every notification posted by NTMovieDocument contains the following elements, at a minimum:


Notification Object The notifying NTMovieDocument


Userinfo


Key Value


NTFilename An NSString object specifying the movie file associated with the NTMovieDocument


The userinfo dictionary may contain a number of additional keys and values that provide information about the movie.  For all notifications other than NTMovieDocumentDidEncounterErrorNotification and NTMovieDocumentDidOpenMovieNotification, the userinfo dictionary will contain the following additional keys and values:


Key Value


NTMovieReferencedFiles An NSDictionary listing other files that contain data referenced by the main movie file (the one whose name is given by NTFilename)


NTMovieVideoFrameRate An NSString object that specifies the number of frames per second at which this movie should normally be viewed


NTMovieVideoBitsPerPixel An NSString object that specifies the degree of video compression in the movie


NTMovieDataSize An NSString object that specifies the size in bytes of the movie data


NTMovieDataRate An NSString object that specifies the data rate, in bytes per second, for the movie playback


NTWidth An NSString object that specifies the “natural” width of the movie video area,  in pixels


NTHeight An NSString object that specifies the “natural” height of the movie video area, in pixels


Each NSString object in the list of values above expresses a double-precision floating-point number.


In addition to the above keys, which are guaranteed to be present except in the case of the notifications mentioned above, the userinfo dictionary can contain these optional keys:


NTVideo An NSDictionary object describing the video media type in detail. <<Details later,  possibly elsewhere.>>


NTSound An NSDictionary object describing the sound media type in detail<<Details later,  possibly elsewhere.>>


Warning: Don't assume the presence of these optional keys.


NTVideo and NTSound are predefined keys for the most commonly found media types.  Keys for other possible types of media are determined by the movie file; the key is the NSString associated with each NTMedia object within an NTMovie object.  Like NTVideo and NTSound, each key that represents a media type has an NSDictionary as its corresponding value.



NTMovieDocumentDidCloseMovieNotification



Posted when the NTMovieDocument is about to be deallocated.  This notification is posted synchronously to the default notification center.



NTMovieDocumentDidDrawNotification



Posted when the NEXTIME server has finished drawing the current video frame.  Receipt of this notification indicates that it's now safe to draw within the NTMovieDocument's NTMovieScreenCell using the Application Kit and Display PostScript.


This notification is posted as a result of editing or any other operation that changes the current position in the movie, including any operation that stops playback.  In addition, it's posted by suspendDrawing (if the movie is currently playing), as well as by display (which is invoked whenever the NSCell containing the video image is redrawn).  However, if drawing is currently suspended, this notification is never posted.


This notification is typically enqueued in the default NSNotificationQueue, not posted synchronously.


See also:  NTMovieDocumentWillDrawNotification



NTMovieDocumentDidEditMovieNotification



Posted when the movie has been edited.  The cut:, delete:, and paste: methods post this notification, which is typically enqueued in the default NSNotificationQueue.



NTMovieDocumentDidEncounterErrorNotification



Posted when an error arises, typically reflecting a problem that the NEXTIME server has encountered.


In addition to the NTFilename key, the userinfo dictionary for this notification can also contain the following keys and values:  


Key Value


NTErrorTitle An NSString object containing the localized error title in a form suitable for use in an alert panel


NTErrorMessage An NSString object containing the localized error message in a form suitable for use in an alert panel


NTErrorDetails An NSString object containing a more detailed message value, typically appropriate for NSLog()


NTErrorCode key An NSString object containing an error code value


Warning: Do not assume the presence of these keys. The contents of the userinfo dictionary are determined by the behavior of installed NEXTIME components.



NTMovieDocumentDidMakeSelectionNotification



Posted when the NTMovieDocument's selection changes. The methods setSelectionStartingPosition:endingPosition: and selectNull cause this notification to be enqueued in the default NSNotificationQueue.



NTMovieDocumentDidOpenMovieNotification



Posted when the NTMovieDocument is initialized with movie data. The methods initWithPasteboard: and initByReferencingFile: cause this notification to be enqueued in the default NSNotificationQueue.



NTMovieDocumentDidPausePlaybackNotification



Posted when playback is paused.  The NTMovieDocument class doesn't post this notification; its pause: method posts the notification NTMovieDocumentDidStopPlaybackNotification instead. NTMovieDocumentDidPausePlaybackNotification is provided for classes conforming to the NTMovieDocument protocol that represent hardware movie documents.  Often, hardware devices need to distinguish between a paused and a played state.  Objects representing such devices should post the notification NTMovieDocumentDidPausePlaybackNotification when the device is paused, and the notification NTMovieDocumentDidStopPlaybackNotification when it's stopped.



NTMovieDocumentDidRenameMovieNotification



Posted when the NTMovieDocument is written to a new file.  (This notification is posted even if the old file was simply a temporary file, such as “UNTITLED.mov”.)  The method writeToFile:atomically: causes this notification to be enqueued in the default NSNotificationQueue.



NTMovieDocumentDidSetPositionNotification



Posted when the NTMovieDocument's current position in time changes.  This notification is posted once by each of the methods setCurrentPosition:, reset:, stepForward:, and stepReverse:.


In addition, the methods play:, fastForward:, and fastReverse: indirectly cause this notification to be posted periodically during playback.  The notification is actually posted by three NTMovieDocument methods that are part of the NTProgressMonitor protocol: object:beganAt:, object:progressedTo:, and object:endedAt:.  The NEXTIME server invokes object:beganAt: when the NTMovieDocument begins playing (whether at normal speed or in fast-forward or fast-reverse mode).  Similarly, the server invokes object:progressedTo: periodically during playback, and object:endedAt: when playback finishes.


This notification is typically enqueued in the default NSNotificationQueue.



NTMovieDocumentDidShowPosterFrameNotification



Posted when the NTMovieDocument is reset to the beginning of the movie.  This notification is enqueued in the default NSNotificationQueue by the method reset:, which stops any playback and causes the poster frame to be displayed.



NTMovieDocumentDidStopPlaybackNotification



Posted when playback is stopped.  A number of methods post this notification when they need to stop a movie that is currently playing (whether at normal speed or in fast-forward or fast-reverse mode).  These methods include pause:, reset:, stepForward:, and stepReverse:.  They also include the playback methods (play:, fastForward:, and fastReverse:) whenever the type of playback (normal, fast-forward, or fast-reverse) is being changed from the current type.  Usually this notification is enqueued, rather than posted synchronously.


This notification is also posted when the movie reaches its end, even if playback is in looped mode. When the end is reached in looped mode, this notification is posted synchronously to the default notification center.



NTMovieDocumentWillDrawNotification



Posted when a new video frame is about to be displayed.  This notification is posted as a result of editing or any other operation that changes the current position in the movie, including any operation that starts playback.  In addition, it's posted by resumeDrawing (if the movie is currently playing), as well as by display (which is invoked whenever the Application Kit redraws the NSCell containing the video image).  However, if drawing by the NEXTIME server is currently suspended, this notification is never posted.


Receipt of this notification indicates that the NEXTIME server will start drawing in the NTMovieScreenCell.  This makes it unsafe to draw in that region using the Application Kit and Display PostScript, as such drawing will be overwritten by the NEXTIME video.  Receipt of the notification NTMovieDocumentDidDrawNotification means it's safe to draw again.  These two notifications don't nest.  That is, the receipt of a single NTMovieDocumentDidDrawNotification notification means that all NEXTIME drawing is done, regardless of how many NTMovieDocumentWillDrawNotification notifications were posted previously.


This notification is posted synchronously to the default notification center.



NTMovieDocumentWillStartFastForwardNotification



Posted just before fast-forward playback begins.  The fastForward: method posts this notification synchronously to the default notification center.



NTMovieDocumentWillStartFastReverseNotification



Posted just before fast-reverse playback begins.  The fastReverse: method posts this notification synchronously to the default notification center.



NTMovieDocumentWillStartPlaybackNotification



Posted just before normal-speed playback begins.  The play: method posts this notification synchronously to the default notification center.
