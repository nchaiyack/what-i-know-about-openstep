Class Description 


NTMovieScreenCell is a subclass of NSActionCell for displaying the video data of a NEXTIME movie.  Clicking the mouse within the cell's frame normally starts playback of the movie.  If the movie is already playing, the click pauses the playback, so that the current video frame is displayed as a still image.  Clicking controls both the video and any accompanying audio (or any other data type in the movie that the NEXTIME server can play back).  


The simplest way to use NTMovieScreenCell is to create an NTMovieScreen object, which automatically creates an associated NTMovieScreenCell.  (However, if the video is to be embedded in text, you instead create an NTMovieAttachment object, which in turn creates an NTMovieScreenCell when it's sent an attachmentCell message.  See the NTMovieAttachment class specification.)


To associate a particular movie with an NTMovieScreenCell, invoke setRepresentedObject: with an NTMovieDocument as the argument.  The argument can also be any other object that conforms to the NTMovieDocument and NTMovieDrawing protocols.  Hereafter it's referred to as the “movie document object.”  For more information on the communication between an NTMovieScreenCell and its movie document object, see “Subclassing NTMovieScreenCell,” below.


Because it's a kind of NSCell, an NTMovieScreenCell responds to a state message.  The state indicates its playback status:  A value of one means the movie is currently playing, and zero means it's paused or stopped.



Resizing the Video Image



Any NEXTIME movie that contains video data also contains information about the video image's suggested height and width, called its natural size.  When an NTMovieScreenCell is first associated with a movie using setRepresentedObject:, it retrieves the movie's natural size from the movie document object.  Normally, the size of NTMovieScreenCell is set to the natural size.  However, if the NTMovieScreenCell receives a drawWithFrame:inView: or drawInteriorWithFrame:inView: message, the message's first argument specifies the size of the NTMovieScreenCell's frame, which might be different from the movie's natural size.


There are four strategies for handling this potential discrepancy in sizes.   The first affects the size of the NTMovieScreenCell, and the others affect the size of the video image.  You can choose a strategy by invoking setResizeMode: with one of four enumeration constants:


• NTMovieScreenCellNormalSizing (the default) always shows the movie at its natural size, forcing the NTMovieScreenCell to grow or shrink to the same size and shape as the video image.


• NTMovieScreenCellContinuousSizing scales the video image's height and width independently to completely fill the NTMovieScreenCell's frame rectangle, even if the aspect ratio (the ratio of height to width) changes in the process.


• NTMovieScreenCellMaintainAspectRatioSizing finds the largest image size that preserves the aspect ratio while fitting inside the frame rectangle.


• NTMovieScreenCellPowerOfTwoSizing scales the image's height and width by the largest positive or negative power of two that lets the image fit within the frame rectangle.  This resize mode also preserves the aspect ratio, but it can yield better image quality and faster resizing than NTMovieScreenCellMaintainAspectRatioSizing.


When the video image is resized, its new height and width are rounded to integral values, ensuring that the image's sides will lie on pixel boundaries.  In all cases, the image is centered within the cell's frame.  If the resized video image doesn't fill the entire frame, the rest of the area inside the frame is drawn in black or a very dark gray.


Resizing takes place when the video is first displayed, and also whenever the NTMovieScreenCell is resized.



Subclassing NTMovieScreenCell



If you subclass NTMovieScreenCell, you should preserve the following behavior of the NTMovieScreenCell class.


NTMovieScreenCell communicates with the NEXTIME server within the updateFrame: method. Override updateFrame: if your subclass uses a hardware playback system or some software playback system other than the NEXTIME server.   If you're using the NEXTIME server but you still need to override this method, invoke the superclass method so you won't have to re-implement the communication with the server.


Within the drawInteriorWithFrame: method, an NTMovieScreenCell sends a display message to its movie document object.  This causes the current frame to be redisplayed if the movie isn't playing.  (See the NTMovieDrawing protocol specification.)


The trackMouse:inRect:ofView:untilMouseUp: method should send a play: or pause: message to the movie document object when the mouse comes up.  Note, however, that the playback state can change by other means as well.  Thus the setRepresentedObject: method should register the NTMovieScreenCell as an observer of the movie document object for notifications of changes in the playback state.  In particular, when the movie has played to the end, the movie document object will post an NTMovieDocumentDidStopPlaybackNotification.  The NTMovieScreenCell can then send the movie document object a reset: message to position the movie at the beginning. 


Whenever the NTMovieScreenCell receives an NSViewFocusChangedNotification, indicating that the NSView containing the NTMovieScreenCell is changing in some way that makes drawing unsafe, the NTMovieScreenCell should send the movie document object a suspendDrawing message.  The NTMovieScreenCell then needs to be informed when it's safe to resume drawing.   One way is for the NTMovieScreenCell to post an enqueued private notification to itself using the NSPostWhenIdle posting style.  Such notifications aren't delivered until the Application Kit has finished its own drawing.  When it receives this notification, the NTMovieScreenCell should send the movie document object a resumeDrawing message.

setNewView:


- (void)setNewView:(NSView *)aView 


Adds the receiver as an observer of the NSViewFocusChangedNotification from aView.  aView is always the NSControl in which the NTMovieScreenCell is located.  This method is invoked indirectly by the Application Kit whenever the NSControl changes.  If aView is nil, drawing is suspended.  (When overriding this method, you should likewise suspend drawing when aView is nil.)


If the receiver is already located in an NSControl, the receiver is removed as an observer of NSViewFocusChangedNotification notifications from that NSControl, and drawing is suspended.



setRepresentedObject:


- (void)setRepresentedObject:(id)anObject 


Sets the movie by associating the receiver with anObject.  If anObject must conform to the NTMovieDocument and NTMovieDrawing protocols, otherwise this method does nothing.  The receiver adds itself as an observer of all notifications from anObject.   If anObject responds to the movieParameters message , the NTMovieScreenCell sends it that message, which returns an NSDictionary that includes NTWidth and NTHeight keys.  The NTMovieScreenCell sets the movie's natural size to these keys' values, and sends the movie document object a suspendDrawing message.


Because NTMovieScreenCell inherits from NSCell, when the receiver is archived it will also archive its represented object.

trackMouse:inRect:ofView:untilMouseUp:


- (BOOL)trackMouse:(NSEvent *)theEvent inRect:(NSRect)cellFrame ofView:(NSView *)controlView untilMouseUp:(BOOL)flag 


Tracks the mouse until the left mouse button goes up.  If flag is NO, tracking will also be terminated if the mouse exits from cellFrame.  A single-click toggles the movie's playback state (playing or paused), unless drawing is suspended, in which case the single-click simply resumes drawing.  Returns YES if the mouse goes up in cellFrame, NO otherwise.


Don't invoke this method directly; it's invoked by the Application Kit.


See also:   - wantsToTrackMouse 



updateFrame:


- (void)updateFrame:(NSRect)frame 


Resizes the video image based on the receiver's current frame rectangle, frame.  If neither frame nor the visible portion of frame has changed since this method was last invoked, no further action is taken.  Otherwise, either the frame or the rectangle that will contain the video image is resized, as determined by the current resize mode.  The NEXTIME server is informed of the new size and location of the video image.


If it hadn't done so previously, the receiver establishes a display context in the NEXTIME server, using a non-zero number (generally self) to identify itself to the server.  The receiver also sends a setViewID: message to its movie document object, using the same non-zero number as the argument.


You should never invoke updateFrame: directly.  This method is invoked by drawInteriorWithFrame:inView:, which is invoked by the Application Kit to draw an NSCell.  However, you might override updateFrame: to implement hardware-driven updates, such as those that refresh a display from an MPEG card.  You would also override it if your subclass uses some software playback system other than the NEXTIME server.  If you override it but still use the NEXTIME server, your implementation should invoke the superclass method.


See also:  - resizeMode
